# 仮説カード テンプレート

1仮説＝1ファイル。`hypotheses/YYYY-MM-DD_<slug>.md` に保存する。カードの目的は、**意思決定者が5秒で仮説文を読み、2分で検証の是非を判断できること**。

## テンプレート

```markdown
---
generated: <YYYY-MM-DDTHH:MM:SS+TZ>
model: <生成に使ったモデル>
status: draft            # draft → 反証生存で approved 候補 / 反証棄却で rejected / 実地検証後に supported | rejected | revised
refutation: 未実施        # 生存（日付・確信度）/ 棄却（日付・確信度）
slug: <英数ケバブケース。ファイル名と一致させる>
---

# <仮説の短い名前>

> **仮説文**: ［顧客セグメント］は、［顧客課題＝すでにとっている行動］があるので、［解決策］を受け入れてくれるはずだ。

| 欄 | 中身 |
|---|---|
| 顧客セグメント | 主語。実在の人物・層。記録中の実名に繋がるなら明記 |
| 顧客課題（行動） | **すでにとっている行動**として書く。願望・感情は不可 |
| 機会の出自 | 顧客インタビュー由来か机上か。机上なら「機会の仮説」と明記 |
| 解決策 | 最小の形。1カード1解決策 |
| 実験 | 誰に・いつ・何をして確かめるか。具体的な相手と場まで |
| 成功基準 | 数値と期限（例: ○月○日までに行動の実在をN名確認） |
| 棄却基準 | 数値と期限（例: 対話N件で該当行動0なら棄却） |
| 根拠 | 参照した記録ファイルへのリンク・引用 |
| リスクと可逆性 | 実験に外部作用があるか。あるなら人間の承認が必要と明記 |

## 反証結果（Step 4 で追記）

判定: 生存 / 棄却（確信度 high/medium/low）
1. セグメント実在性: …
2. 行動の実在（すり替え検査）: …
3. 自社問題の混入: …
4. 支払意思・実行可能性: …

生存の場合→「生き残る条件」を実験設計に織り込む。
棄却の場合→「復活に必要な事実」を明記して保存する。

## 実地検証の結果（Step 5 で追記）

実施日・相手・確認できた行動・確認できなかったこと・判定（支持/棄却/修正）・記録への書き戻し先
```

## 記入例（架空・机上生成の例）

```markdown
> **仮説文**: 毎月手作業で顧問先向けニュースレターを作っている小規模士業は、
> 毎月数時間かけて Word で原稿を組む行動をすでにとっているので、
> 過去号と顧問先情報から下書きを自動生成するサービスを受け入れてくれるはずだ。

| 顧客セグメント | 顧問先20件未満の税理士・社労士（記録中: C先生） |
| 顧客課題（行動） | 毎月末に3〜4時間かけてニュースレターを Word で手作り（顧客メモ 2026-06 で観測） |
| 機会の出自 | 机上＝**機会の仮説**（C先生の行動は記録由来・本人への確認は未実施） |
| 実験 | C先生との次回定例（7月第2週）で、直近号をどう作ったか30分聞く。売り込みなし |
| 成功基準 | 7月末までに「作成に月3時間以上」を本人の口から確認＋現物を見せてもらう |
| 棄却基準 | 聞き取り2件で「実は苦にしていない/外注済み」なら棄却 |
```

**ガードの再掲**: 仮説文の4要素（セグメント・行動・解決策・実験）のどれかが埋まらないカード、棄却基準のないカードは保存しない。埋まらないという事実自体が「まだ仮説を立てる段階ではない」というシグナルである。
